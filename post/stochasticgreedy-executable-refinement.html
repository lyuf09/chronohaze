从一套框架到真正会运行的随机算法：StochasticGreedy 的 executable refinement

Feier Lyu · 2026年10月3日 · 约 7 分钟

Isabelle/HOL · Submodular Maximization · StochasticGreedy · Randomized Algorithms · Formal Verification

把算法、概率语义、近似证明和可执行代码放进同一条 machine-checked chain。

几个月前写这个项目的时候，我最后留下了一个很具体的 gap。

当时 StochasticGreedy 的 theorem-level development 已经相当完整：uniform with-replacement sampling model、one-step expected-gain bound、gap recurrence、最终的 approximation guarantee，以及 oracle-cost theorem 都已经存在。但这些概率分析和真正可以执行的 stochastic algorithm 仍然是分开的。

换句话说，我已经证明了“如果每一步服从这个 sampling model，那么可以得到这样的 expected progress”，也有 deterministic trace 可以模拟随机采样结果，但还没有证明：

真正由随机比特驱动、能够实际运行的程序，它产生的概率分布，就是前面分析所使用的那个概率模型；而最终的 approximation guarantee，也确实属于这同一个程序。

最近这一段工作基本上就是在补这个洞。

而且补完之后，我觉得这个项目的性质又变了一次。它不再只是一个带有 executable examples 的 theorem library，而开始真正触碰到我一直很想做的那件事：把算法、概率语义、近似证明和可执行代码放进同一条 machine-checked chain 里。

上一阶段停在哪里

StochasticGreedy 本身的想法并不复杂。

Classical greedy 每一轮扫描所有剩余元素，计算 marginal gain，然后选择最大的一个。StochasticGreedy 则只随机抽一个较小的 candidate pool，再在这个 sample 里面选 marginal gain 最大的元素。

如果 sample size 选得合适，就可以用远少于 full scan 的查询次数，仍然在期望意义下得到接近 classical greedy 的 approximation guarantee。

此前 repo 中已经有完整的数学分析。

在 set-level 的抽象模型里，我定义了 uniform with-replacement sampling space，并证明 sampled pool 击中 optimal residual elements 的概率；再通过 weighted sampling 和 expected one-step gain 的接口，把这种概率信息变成

expected gain ≥ (sampling factor / k) · current gap

形式的 progress inequality。

之后就是熟悉的 recurrence：当前解离 OPT 还有一个 gap，每一步在期望意义下消掉其中一定比例，迭代 k 次以后得到最终的 exponential bound，再实例化 sample size，就得到 1 - 1/e - eps 风格的 approximation guarantee。

数学上这条线已经闭合。

问题在于：这里的 expectation 还属于抽象的 sampling model，而不是一个真正 executable randomized program 的输出分布。

这两个东西在直觉上当然应该是同一个算法。但 formal verification 最有意思的地方就在这里——“当然应该是”不是 theorem。

所以这次我想证明的恰好就是这个等号。

第一层：先把随机采样本身变成 verified executable object

最底层需要解决的是 sampling。

我使用 Isabelle 的 executable randomized algorithms infrastructure 写了真正由 random bits 驱动的 uniform sampler，并把多个独立 draw 组合成 uniform-with-replacement sample pool。

单纯写出 sampler 并不难，真正重要的是证明它的 executable semantics 与之前 theorem line 中的数学模型一致。

也就是说，不只是：

这个程序看起来像是在均匀抽样。

而是形式化地证明它对应的 spmf / pmf 正好等于此前定义的 uniform-with-replacement distribution。

这一层之后，random bits、executable sampler 和 abstract sample space 第一次真正连在了一起。

对我来说这是一个很重要的区别。以前的 uniform_wr_space 是分析对象；现在它同时也是一个实际程序的 denotational semantics。

第二层：把不可执行的 argmax 换成真正的 list algorithm

另一个很典型的问题是 argmax。

在纯数学证明里，我完全可以写：

choose an element attaining the maximum marginal gain

只要有限性和非空性成立，存在性证明就足够了。

但这种 specification 往往会依赖 Hilbert choice。它对 theorem proving 很自然，对 code generation 却没有意义：证明“存在一个最大值元素”和告诉程序“怎样找到它”是两件不同的事。

所以这一层我另外实现了一个 total list-based argmax。

它顺序扫描 candidate list，维护当前最优元素，并证明：

  • 返回值一定来自输入 list；
  • 返回值的 score 不小于任何其他 candidate；
  • 它对应 abstract argmax 所要求的最大 marginal gain；
  • 实现可以直接进行 SML code generation。

然后这个 list argmax 再和 executable sampler 组合成真正的一步 stochastic greedy update。

这一步做完之后，程序已经不需要任何抽象 choice：sample pool 是真的抽出来的，最大 marginal gain 元素也是真的算出来的。

从一步到真正的 randomized runner

接下来我定义了 recursive randomized runner。

单轮可执行算法会从当前 solution 中计算 remaining elements，以 uniform-with-replacement 的方式抽取 candidate pool，然后执行经过验证的 list-based selection procedure。

完整的 randomized runner 则使用 Isabelle executable randomized-algorithm framework 提供的 probabilistic bind structure，递归组合这些步骤。

到这里已经可以给它 seed，然后真正运行：同一个 seed 对应确定的 random bits，不同 seed 可以产生不同的 stochastic trajectory，而且整条算法可以导出到 SML。

但能够运行仍然只是第一步。

如果我要说这是 verified stochastic greedy，我还需要证明这个 runner 的整个 probability distribution 是对的。

真正关键的 bridge：program distribution 等于 proof distribution

这一部分是最近 development 里我最在意的地方。

核心的 semantic result 直接识别 executable randomized step 所诱导的 distribution 与 approximation analysis 中使用的 abstract uniform-with-replacement model。与此同时，可执行开发也建立了 randomized runner 应有的 well-formedness properties，包括 almost-sure termination 与 support 中所有输出的 feasibility。

这个 distributional correspondence 正是让既有 expected-gain analysis 可以复用于实际 executable program 的桥梁。

接着我证明，executable step 的 expected objective increment 与此前 abstract sampling analysis 中出现的 expected gain 完全一致。因此原有的 one-step theorem 不需要重新证明，而可以直接 transfer 到程序：

expected gain ≥ (sampling factor / k) · (f(OPT) - f(S))

这也是我非常喜欢整个 architecture 的一个地方。

之前把 sampling、weighted one-step analysis 和 recurrence 刻意拆开，看起来会增加一些文件和 abstraction，但当 executable semantics 真正接进来的时候，这种 modularity 开始回报：新的程序层只需要证明它实现了原来的 semantic interface，后面的 approximation mathematics 可以整个复用。

approximation guarantee 现在属于“这个程序本身”

single-step expectation 接上之后，下一步就是把 expectation 推过整个 recursive runner。

这里我定义了 full run 的 expected objective value，并证明 recursive expectation identity：执行一轮 randomized step 后，再继续执行剩余轮数，其 expectation 可以按照对应 PMF 的 bind structure 分解。

有了这个 identity，就可以直接在 executable distribution 上做 recurrence induction。

最后得到的是一个真正的 run-level theorem。

对于合适的 epsilon-driven sample size，执行 k 轮的 randomized algorithm：

  1. almost surely terminates；
  2. 所有可能输出都满足 feasibility 和 cardinality constraint；
  3. 并且同一个程序的输出 PMF 满足
(1 - 1/e - eps) · f(OPT) ≤ E[f(output)]

这里最重要的不是 approximation ratio 本身。

1 - 1/e - eps 当然是我们一开始就知道想要得到的结果。

真正不同的是，现在右边这个 expectation 不再属于一个人为定义的 abstract recurrence，也不是“假设某个 stochastic process 每一步满足……”。

它就是：实际 executable randomized runner 的输出 distribution。

之前 theorem 和 program 是两条平行的线；现在它们在这里变成了同一个对象。

再把它实例化成真正可执行的 weighted coverage

有了 generic runner 以后，我还做了一个 concrete weighted-coverage instance。

这里其实又出现了一个很实际的 formalisation 问题。

数学 theorem 最自然地在 real-valued objective 上陈述，但真正 code generation 时，如果为了比较 marginal gains 把大量 real arithmetic 搬进程序，并不是我想要的实现。

所以 concrete executable layer 使用 exact natural-number weights 和整数式的 coverage score，而 specification layer 仍然使用 real-valued submodular objective。

然后证明两种 score comparison 对 argmax 产生完全相同的选择。

这样做以后，程序运行的是简单的 exact discrete computation，而 approximation theorem 仍然可以在之前的 real-valued mathematical framework 中陈述。

最后这个具体 weighted-coverage runner 同样继承：

  • almost-sure termination；
  • feasible outputs；
  • 1 - 1/e - eps expected approximation guarantee；
  • SML code generation。

这一步对我来说也很重要，因为它说明 executable refinement 不是只停在一个 polymorphic toy function 上，而是真的可以走到 concrete objective instance。

oracle cost 也开始属于实际程序

在之前的 theorem line 中，我已经有 trace-level oracle accounting。

这一次则进一步把 counter 搬进 randomized runner 本身。

我还开发了一个记录 score evaluations 的 instrumented executable runner。对应的 refinement theorem 证明，擦除 instrumentation 后会精确恢复原来的 randomized semantics。

在当前 baseline implementation 下，一轮对 sample pool 做 sequential argmax comparison，整个 n-round runner 的 score evaluation 有一个显式 upper bound；再按照 marginal gain 需要的 objective evaluations，可以继续得到对应的 oracle budget。

于是对于 weighted-coverage instance，现在可以在同一个 theorem package 中同时说：

  • 程序 almost surely terminates；
  • 输出始终 feasible；
  • 它满足 expected approximation guarantee；
  • 而它的实际 evaluation count 也满足形式化的 budget bound。

这比我以前单独证明一个 asymptotic complexity expression 更让我满意，因为 cost 已经不是贴在算法旁边的一张标签，而是被 instrumented execution 本身带出来的 quantity。

正在继续的 executable refinements

counting development 也揭示了若干 implementation-level 的机会，可以进一步减少冗余的 oracle work。我目前正在细化 executable selection routine，同时证明这些优化保持完全相同的 randomized semantics，因此也能继承既有的 approximation guarantees。

这部分工作比 approximation theorem 本身更接近 verified performance engineering。我也开始通过具体执行与 benchmark，研究形式化验证的 cost model 与实际 runtime behaviour 之间的关系。

我现在怎么理解这个项目

我之前写“从一个定理到一套框架”的时候，觉得这个项目最大的变化是：它不再只是 Nemhauser–Wolsey theorem 的形式化，而开始成为一套可以容纳 classical greedy、LazyGreedy 和 StochasticGreedy 的 library。

现在我觉得又可以往前加一句。

一个 formal algorithm library 如果只有 theorem 和 executable code 并排放着，其实还不够。

真正让我感兴趣的是证明下面这条 chain：

mathematical specification → executable implementation → probability semantics → expected progress → global approximation theorem → concrete executable instance → resource accounting

而且每一个箭头本身都是 theorem。

这也是这次 executable refinement 对我来说真正重要的地方。

export_code 本身并不难，写一个随机程序也不难，证明一个 abstract expectation inequality 我之前也已经做完了。

困难的是证明最后导出的那个程序，和你在 theorem 里分析的随机算法，真的就是同一个对象。

Scope note. 2026 年正式发表于 AFP 的条目覆盖 classical greedy 与 verified stateful lazy-greedy variant。本文描述的 StochasticGreedy development——包括 executable randomized semantics、run-level expected approximation guarantee 与 resource-accounting layer——是对该条目进行扩展的 ongoing post-publication work。

From a Framework to a Randomized Algorithm That Actually Runs: Executable Refinement of StochasticGreedy

Feier Lyu · October 3, 2026 · ~7 min read

Isabelle/HOL · Submodular Maximization · StochasticGreedy · Randomized Algorithms · Formal Verification

Putting the algorithm, its probability semantics, its approximation proof, and executable code into one machine-checked chain.

A few months ago, this project still had one very specific gap.

The theorem-level development of StochasticGreedy was already fairly complete: a uniform-with-replacement sampling model, a one-step expected-gain bound, a gap recurrence, the final approximation guarantee, and an oracle-cost theorem were all in place. The probabilistic analysis and an actually executable stochastic algorithm, however, remained separate.

In other words, I had proved that if each step followed the sampling model, then it made the required expected progress. I also had deterministic traces that could simulate sampled outcomes. What I had not yet proved was this:

The probability distribution produced by a real program driven by random bits is exactly the model used in the earlier analysis, and the final approximation guarantee belongs to that very same program.

The recent work was essentially about closing this gap.

Once it was closed, the character of the project changed again. It was no longer just a theorem library with executable examples beside it. It began to reach what I had wanted all along: one machine-checked chain joining the algorithm, probability semantics, approximation proof, and executable code.

Where the previous stage stopped

The idea behind StochasticGreedy is simple.

Classical greedy scans every remaining element in each round, computes every marginal gain, and chooses the largest. StochasticGreedy samples a much smaller candidate pool and chooses the element with maximum marginal gain only within that sample.

With an appropriate sample size, it uses far fewer queries than a full scan while retaining, in expectation, an approximation guarantee close to classical greedy.

The repository already contained the full mathematical analysis. In a set-level abstract model, I defined a uniform-with-replacement sampling space and proved the probability that the sampled pool hits the optimal residual elements. Weighted sampling and an expected one-step-gain interface then turned that probability into a progress inequality of the form

expected gain ≥ (sampling factor / k) · current gap

The familiar recurrence follows. The current solution has a gap from OPT; every step removes a fixed fraction of that gap in expectation; after k iterations, this yields an exponential bound; instantiating the sample size then gives a 1 - 1/e - eps-style approximation guarantee.

Mathematically, that line was complete.

The problem was that the expectation still belonged to an abstract sampling model, not to the output distribution of an executable randomized program.

Intuitively, they should of course describe the same algorithm. But this is exactly what makes formal verification interesting: “of course” is not a theorem.

The equality between those two objects is what I set out to prove.

Layer one: making random sampling a verified executable object

The bottom layer is sampling.

Using Isabelle's infrastructure for executable randomized algorithms, I implemented a uniform sampler driven by actual random bits and combined independent draws into a uniform-with-replacement sample pool.

Writing the sampler itself was not difficult. The important part was proving that its executable semantics agrees with the mathematical model used by the theorem line.

The claim is not merely:

This program looks as though it samples uniformly.

Instead, the corresponding spmf / pmf is formally proved equal to the previously defined uniform-with-replacement distribution.

At that point, random bits, the executable sampler, and the abstract sample space are connected for the first time.

This distinction matters to me. Previously, uniform_wr_space was an object of analysis. It is now also the denotational semantics of a real program.

Layer two: replacing non-executable argmax with a real list algorithm

Another typical issue is argmax.

In a purely mathematical proof, I can write:

choose an element attaining the maximum marginal gain

Once finiteness and nonemptiness are established, an existence proof is enough.

Such a specification often relies on Hilbert choice. That is natural in theorem proving but meaningless for code generation: proving that a maximizer exists and telling a program how to find one are different tasks.

I therefore implemented a total, list-based argmax. It scans the candidate list, maintains the current best element, and comes with proofs that:

  • the returned element belongs to the input list;
  • its score is at least that of every other candidate;
  • it realizes the maximum marginal gain required by the abstract argmax; and
  • the implementation supports direct SML code generation.

The list argmax is then combined with the executable sampler to form a genuine stochastic-greedy update.

At this point, the program no longer depends on any abstract choice: the sample pool is actually drawn, and the maximum-marginal-gain element is actually computed.

From one step to a real randomized runner

The next object is a recursive randomized runner.

A single executable round computes the remaining elements, samples a candidate pool uniformly with replacement, and applies the verified list-based selection procedure.

The full randomized runner then composes these steps recursively using the probabilistic bind structure provided by Isabelle's executable randomized-algorithm framework.

It can now be given a seed and actually run. The same seed determines the same random bits; different seeds can produce different stochastic trajectories; and the complete algorithm can be exported to SML.

But being able to run it is only the first step.

To call it verified stochastic greedy, I still needed to prove that the entire output distribution of the runner is the right one.

The key bridge: program distribution equals proof distribution

This is the part of the recent development that matters most to me.

The central semantic result identifies the distribution induced by the executable randomized step with the abstract uniform-with-replacement model used in the approximation analysis. Along the way, the executable development establishes the expected well-formedness properties of the randomized runner, including almost-sure termination and feasibility of supported outputs.

This distributional correspondence is the bridge that allows the existing expected-gain analysis to be reused for the actual executable program.

I then prove that the expected objective increment of the executable step is exactly the expected gain appearing in the earlier abstract sampling analysis. This allows the abstract one-step progress bound to transfer directly to the executable program:

expected gain ≥ (sampling factor / k) · (f(OPT) - f(S))

This is where the architecture begins to repay its earlier abstractions. Sampling, weighted one-step analysis, and recurrence were deliberately separated. Once executable semantics satisfies the old semantic interface, the approximation mathematics above it can be reused wholesale.

The approximation guarantee now belongs to the program itself

After connecting the single-step expectation, the next task is to propagate expectation through the full recursive runner.

I define the expected objective value of a full run and prove a recursive expectation identity: after one randomized step, the expectation of the remaining run decomposes according to the bind structure of the corresponding PMF.

This identity makes it possible to carry out the recurrence induction directly over the executable distribution.

The final result is a genuine run-level theorem. For the appropriate epsilon-driven sample size, the k-round randomized algorithm:

  1. terminates almost surely;
  2. produces only feasible outputs satisfying the cardinality constraint; and
  3. has an output PMF satisfying
(1 - 1/e - eps) · f(OPT) ≤ E[f(output)]

The important point is not the approximation ratio itself. 1 - 1/e - eps was the target from the beginning.

What has changed is the right-hand side. This expectation no longer belongs to a manually defined abstract recurrence or to a hypothetical stochastic process satisfying a one-step assumption.

It is the output distribution of the executable randomized runner.

The theorem and the program were once parallel lines. Here, they become the same object.

Instantiating it with genuinely executable weighted coverage

With the generic runner in place, I also built a concrete weighted-coverage instance.

This exposes another practical formalization issue. The mathematical theorem is most naturally stated for a real-valued objective. For code generation, however, I did not want marginal-gain comparisons to carry unnecessary real arithmetic into the implementation.

The concrete executable layer therefore uses exact natural-number weights and an integer coverage score, while the specification layer retains the real-valued submodular objective.

I then prove that the two score comparisons cause argmax to make exactly the same choices.

The program consequently performs simple exact discrete computation, while the approximation theorem remains stated in the original real-valued mathematical framework.

The resulting weighted-coverage runner inherits:

  • almost-sure termination;
  • feasible outputs;
  • the 1 - 1/e - eps expected approximation guarantee; and
  • SML code generation.

This matters because the executable refinement no longer stops at a polymorphic toy function. It reaches a concrete objective instance.

Oracle cost now belongs to the actual program too

The earlier theorem line already contained trace-level oracle accounting. This time, I moved the counter into the randomized runner itself.

I also developed an instrumented version of the executable runner that records score evaluations. A refinement theorem shows that erasing the instrumentation recovers the original randomized semantics exactly.

For the current baseline implementation, sequential argmax comparison over one sample pool gives an explicit upper bound on score evaluations for the full n-round runner. Accounting for the objective evaluations required by a marginal gain then yields the corresponding oracle budget.

For the weighted-coverage instance, the same theorem package can now state that:

  • the program terminates almost surely;
  • every output is feasible;
  • the expected approximation guarantee holds; and
  • the actual evaluation count satisfies a formal budget bound.

This is more satisfying than proving an asymptotic complexity expression beside the algorithm. Cost is no longer a label attached to the program; it is a quantity produced by the instrumented execution itself.

Ongoing Executable Refinements

The counting development also revealed several implementation-level opportunities for reducing redundant oracle work. I am currently refining the executable selection routine while proving that these optimizations preserve the same randomized semantics and therefore inherit the existing approximation guarantees.

This part of the project is closer to verified performance engineering than to the approximation theorem itself. I am also beginning to use concrete executions and benchmarks to study how the formally verified cost model relates to practical runtime behaviour.

How I now understand the project

When I previously wrote “from one theorem to a framework,” the central change was that the project had grown beyond a formalization of the Nemhauser–Wolsey theorem into a library that could contain classical greedy, LazyGreedy, and StochasticGreedy.

I would now add one more sentence.

A formal algorithm library is not yet enough if it merely places theorems and executable code side by side.

What interests me is proving the following chain:

mathematical specification → executable implementation → probability semantics → expected progress → global approximation theorem → concrete executable instance → resource accounting

Every arrow in that chain is itself a theorem.

That is the real importance of this executable refinement for me.

export_code is not difficult by itself. Writing a randomized program is not difficult either, and I had already proved the abstract expectation inequality.

The difficult part is proving that the program eventually exported is genuinely the same randomized algorithm analyzed by the theorem.

At that point, formalization is no longer only about checking whether a mathematical proof is correct. It begins to answer a much more implementation-facing question: Is the thing we actually run really the thing we proved correct?

That is probably the direction I am most interested in continuing to explore.
